Killing a rate-limit bug by moving an API call from the browser to the build

August 1, 2026 · 3 min read
Roxy
Offensive Security Researcher

A client's "Projects" page pulled repo data live from the GitHub API, client-side, on every page load — no auth token, since it was running in the visitor's browser. That's a 60 requests/hour cap shared across every visitor on the same IP or NAT block. Anyone behind a shared IP — an office, a university, a CGNAT ISP — could land on the page with the quota already burned by someone else and get a silent empty grid.
